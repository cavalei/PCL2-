# PCL 原版下载恢复工具（干净版）

为 [PCL2](https://github.com/Meloong-Git/PCL) 2.99.0.0 生成「恢复原版下载」的可运行副本。

**单文件、免安装、完全离线**：不联网、不写注册表、不装服务、不启动任何进程、不需要管理员权限。

> 本工具为第三方作品，**不是 PCL 官方发布**，与原作者无关。

---

## 为什么有这个

2.99.0.0 的下载页会按条件隐藏原版下载入口。网上流传的补丁工具有些夹带私货，无法验证来源。

这个仓库的做法是：**源码公开 + 可自行编译 + 构建产物带指纹**。你可以不信任任何人的二进制，直接看代码、自己编译。

---

## 用法

### 图形界面

1. 双击 `PCL原版下载恢复-干净版.exe`
2. 点「选择文件」，或直接把 `PCL2.exe` 拖进窗口
3. 校验通过后，点「生成恢复下载的副本…」
4. 关闭原启动器，运行新生成的副本

原启动器不会被修改，只生成一个新文件。

### 命令行

```powershell
# 检查是否支持：0=可处理  2=已处理  1=不支持或出错
.\PCL原版下载恢复-干净版.exe --check "PCL2.exe"

# 生成副本（不覆盖原文件，不覆盖已有文件）
.\PCL原版下载恢复-干净版.exe --patch "PCL2.exe" "PCL2.原版下载恢复.exe"

# 查看版本和自身 SHA-256
.\PCL原版下载恢复-干净版.exe --version
```

## 校验方式（v2.0 起改变）

早期版本用「整文件 SHA-256 白名单」。问题是同一版本会存在多个官方构建：

- 赞助后直接下载的构建，内嵌了赞助标识（一段 Base64 数据）
- 通过内置更新累积升级的构建，该区域是 `EmptyMark` 占位

**两者代码完全一致，仅元数据不同，哈希却不同**，白名单会把正常构建误拒。

v2.0 改为按「构建布局 + 指令」校验，三道检查：

| 检查 | 内容 |
|---|---|
| **1. 文件长度** | 必须等于 5980160 或 5985280 字节 |
| **2. 补丁点指令** | 目标位置那 24 字节必须与已知原版一致 |
| **3. 可见性字节** | 必须为 `0x18`（`ldc.i4.2`，即 Collapsed） |

三项全过才允许生成副本，否则一个字节都不写。

### 写入前后的差异断言

生成副本时，工具会逐字节比对输入与输出：

> **输出必须与输入只在这两处不同，其余字节必须完全一致。**

任何超出补丁区域的改动都会让工具中止并删除输出。所以即使源码被误改，也不会产出坏文件。

## 支持的构建

| 文件长度 | 说明 |
|---:|---|
| 5,980,160 | 官方仓库附带构建 |
| 5,985,280 | 官方发布构建（含赞助版与更新版变体） |

处理内容：

- 下载页的原版版本列表加载器
- 版本修改页的原版入口

**不处理**：整合包安装限制（保持不变）、微软登录、正版校验、主题、更新、CurseForge。

## 自己验证

### 1. 核对官方发布的哈希

每次 `push` 或打 tag，GitHub Actions 会编译并打印产物 SHA-256，同时上传为 Artifact。

```powershell
certutil -hashfile "PCL原版下载恢复-干净版.exe" SHA256
```

### 2. 自己编译，和自己手里的 EXE 对比

```powershell
.\build.ps1
```

用 Windows 自带的 csc（.NET Framework 4.8），无第三方依赖。编译产物在 `dist/`。

两份 EXE 逐字节对比时，**差异只应有 2 处**：

- `0x88` 附近：PE 校验和（2 字节）
- 元数据里的 MVID（16 字节）

这是 csc 每次编译都会变的字段，不是代码差异。

### 3. 直接读源码

`src/PclDownloadRestoreClean.cs` 约 400 行，核心逻辑在 `Patcher` 类。全文没有：

- 网络请求（`HttpClient` / `WebClient` / `Socket`）
- 进程启动（`Process.Start`）
- 注册表写入
- Base64 或动态加载

产物的 PE 导入表里只有 `mscoree.dll`（.NET 引导桩），没有任何原生 API。

## 为什么会被杀软报毒

这类「读取一个 EXE、改写并另存」的工具，很容易被启发式规则标成 `HackTool` 或 `Patcher`——因为它**行为上确实在修改别的可执行文件**。

这和真正的木马（下载器、内存加载、持久化）不是一回事：

| 特征 | 本工具 | 银狐类木马 |
|---|---|---|
| 联网下载 | 无 | 必需 |
| 内存注入 | 无 | 常见 |
| 注册表 / 计划任务持久化 | 无 | 必需 |
| 原生 API 调用 | 无 | 常见 |
| 需要管理员权限 | 不需要 | 通常需要 |

如果仍然不放心，用源码自己编译，或干脆别用。
